# Demo凭证修复（demo-rounds-2.1）

## 原因

上一版前端只检查浏览器localStorage中有没有tokens，不验证其在当前服务上是否仍有效。旧部署、另一API环境或数据库更换留下的缓存因此会一直收到401 `Invalid Demo credential`，原实现没有恢复路径。服务端仍正确拒绝无效签名，不是Rider/Driver业务逻辑失败。

## 修复

- 新增受原签名鉴权保护的只读 `GET /api/demo/session`；不会返回tokens或签名秘密。
- 前端启动时验证旧缓存；有效凭证和已有选中案件保持不变。缓存按API地址隔离并兼容旧key迁移。
- 失效凭证自动建立一次新隔离工作区，并显示恢复提示。并发启动只建立一个会话。
- 401允许一次只读列表重试；**POST、结案、上传、Driver回应等写操作不自动重放**，也不把403角色拒绝当凭证失效。
- 校验接口临时故障时保留已有缓存，不清空工作区。刷新后可重试。
- 页面和JavaScript使用no-store，避免正常刷新仍拿到旧恢复逻辑。
- 后端鉴权和Rider-only提交限制没有放宽。服务器数据库及已有案件没有删除。

## 旧案件说明

无效凭证不能证明旧工作区身份，不能靠解码session_id或信任浏览器来重新绑定旧案件。自动恢复建立新工作区，因此旧案件不会显示在新工作区，但服务端记录没有被删除。已有仍有效的工作区会原样保留。

## 验收

97项Python回归通过；新增4项服务端会话校验测试。6项离线JS测试覆盖并发启动、有效会话保留、中途401写操作不重放、GET最多一次重试、403不续建及瞬态故障不清缓存。真实浏览器用无效旧缓存重现原错误，恢复后验证Rider/Driver/Admin导航共用同一新工作区，并执行Rider提交→Driver同意路线。实际结果见对应JSON。
